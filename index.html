I · Generalidades y marco teórico

Presentación del proyecto

Este apartado describe el tema, el contexto del problema y los conceptos que orientan el análisis del sistema propuesto.

📘

Introducción

La gestión de un consultorio dental requiere organizar información administrativa y clínica que se genera durante la atención. Cuando los datos de pacientes, citas, consultas y tratamientos se registran en diferentes soportes, pueden aparecer duplicaciones, demoras para localizar antecedentes y dificultades para dar seguimiento a la atención. Este proyecto propone analizar y diseñar un sistema de información que centralice esos registros y facilite su consulta por usuarios autorizados. El trabajo se desarrollará aplicando análisis estructurado y orientación a objetos mediante UML.

🗂️

Requerimientos

Para nuestro caso la Odontologa Angela Merma, nos dijo que queria tener a la mano el registro de sus pacientes, ella lo registraba todo en cuadernos desde las citas hasta los cobros que hacia por sus servicios, se le hacia tedioso cada que necesita ver el "el historial" de cada paciente,tambien nos comento que no tenia buena organizacion en el tema de consultas que tambien tomemoes en cuenta ese aspecto.

⚠️

Planteamiento del problema

La información de pacientes, citas y tratamientos puede encontrarse dispersa o gestionarse de manera manual, lo que dificulta la búsqueda de antecedentes, el seguimiento de citas y la elaboración de reportes. El proyecto estudiará estas dificultades y definirá cómo un sistema centralizado podría apoyar el control de gestión y la continuidad del registro clínico.

🎯

Marco teórico

Conceptos fundamentales

Sistema de información

Conjunto organizado de personas, procedimientos y recursos tecnológicos que permiten registrar, procesar, almacenar y consultar información para apoyar actividades y decisiones.

Gestión de consultorio dental

Organización de tareas como registro de pacientes, agenda de citas, seguimiento de consultas, tratamientos y reportes administrativos.

Historial clínico dental

Registro organizado de antecedentes relevantes, consultas, evaluaciones, diagnósticos y tratamientos realizados o planificados por profesionales autorizados.

Análisis estructurado

Enfoque que describe qué hace el sistema mediante procesos, entradas, salidas, almacenes de datos y flujos de información.

Orientación a objetos

Enfoque que representa el dominio mediante objetos con atributos y operaciones, agrupados en clases que colaboran para cumplir responsabilidades.

UML

Lenguaje de modelado visual que permite representar, entre otros aspectos, actores, casos de uso, clases, interacciones y actividades de un sistema.

Investigación

Problema, objetivos y justificación

Objetivo general

Analizar y diseñar un sistema de control de gestión e historial clínico para un consultorio dental, aplicando el análisis estructurado y el paradigma orientado a objetos con UML, con el propósito de definir una solución organizada para administrar información de pacientes, citas, consultas y tratamientos.

Objetivos específicos

  • Identificar las necesidades y dificultades del proceso actual de gestión dental.
  • Reconocer a los usuarios, sus responsabilidades y la información que utilizan.
  • Definir requisitos funcionales y no funcionales del sistema propuesto.
  • Modelar procesos y flujos de información mediante análisis estructurado.
  • Representar la estructura y el comportamiento del sistema mediante diagramas UML.
  • Proponer una arquitectura funcional que permita mantener registros organizados y protegidos.

Justificación técnica

El trabajo permite aplicar los métodos estudiados en la asignatura a un caso concreto. El modelado previo ayuda a aclarar procesos, datos, responsabilidades y límites antes de implementar software.

Justificación práctica

Una propuesta integrada podría reducir la duplicación de registros, facilitar la búsqueda de información y apoyar el seguimiento de citas y tratamientos. Estos beneficios son esperados y deberán evaluarse; no se afirman como resultados ya medidos.

Un paciente puede tener muchas citas y consultas; cada cita corresponde a un paciente y puede asociarse a un odontólogo; un historial clínico pertenece a un paciente y reúne sus consultas; una consulta puede documentar uno o varios tratamientos. Las multiplicidades seran representadas explícitamente en el diagrama final.

Flujo de caso de uso: registrar una consulta

Odontólogo inicia sesión
→
Busca al paciente
→
Revisa historial

Registra consulta y guarda

Precondiciones

  • El usuario ha iniciado sesión.
  • El usuario tiene permiso para registrar atención clínica.
  • El paciente existe o se registra según el procedimiento definido.

Resultado esperado

La consulta queda asociada al paciente, con fecha, profesional y contenido clínico necesario; el sistema confirma el registro y conserva trazabilidad de la modificación.

Requisitos no funcionales

Seguridad

Autenticación, permisos por rol, sesiones seguras y acceso restringido a datos clínicos.

Privacidad

Recopilar solo datos necesarios y evitar que información clínica aparezca en páginas públicas o reportes abiertos.

Usabilidad

Formularios claros, navegación consistente, mensajes de validación y búsqueda comprensible.

Integridad

Validar campos obligatorios y mantener relaciones consistentes entre pacientes, citas y consultas.

Disponibilidad

Definir copias de seguridad y procedimientos de recuperación apropiados para el entorno de uso.

Mantenibilidad

Organizar el sistema por módulos y documentar modelos, reglas y cambios.

Consideraciones transversales

Seguridad, privacidad y uso responsable

Protección de información clínica

El historial clínico contiene información sensible. somos consientes de la responsabilidad que eso implica, permisos mínimos necesarios, autenticación, registro de accesos, copias de seguridad y procedimientos para corregir errores, somos agradecidos con la confianza que se nos esta dando.

Publicación del sitio académico

Este sitio está pensado para presentar el proyecto y sus modelos, no para almacenar historias clínicas reales. No publicar nombres, teléfonos, fotografías, diagnósticos ni capturas de pacientes.

Conclusión preliminar

El análisis y diseño de un sistema de control de gestión e historial clínico puede ayudar a comprender cómo integrar los procesos administrativos y clínicos de un consultorio dental. La aplicación complementaria del análisis estructurado y UML permite estudiar los flujos de información y representar la estructura y el comportamiento de la solución.
